# RSML (Really Simple Mailing Lists)

> _"Python-based Mailing List Server System"_

## Core premise

### User Functionality

This section outlines all the functionality related to the user

#### Subscription

`POST /list/subscribe`

Users can subscribe to the mailing list through HTTP (with an `email` field in a JSON-formatted body), which will send an email as outlined below.

#### Verification

`GET /list/verify?email=X&token=Y`

After subscription, the server will send the user an email verifying their subscription to the mailing list.

The `token` key must contain a `hex(HMAC-SHA256(server_secret, "verify:" + email))`-generated token.

#### Unsubscription

`GET /list/unsubscribe?email=X&token=Y`

Users can unsubscribe through an URL given with every email, the link is also sent through the `List-Unsubscribe` and `List-Unsubscribe-Post` headers (RFC 8058).

The link's `token` key must contain a `hex(HMAC-SHA256(server_secret, "unsub:" + email))`-generated token.

#### Posting

`To: dev@localhost`

Users can send an email to the list (if the `posting` feature is enabled), via an email configured by the server.

RSML does not implement SMTP. An external MTA is responsible for receiving messages addressed to `posting_email` and providing them to RSML through LMTP.

### Server Functionality

This section outlines all the server-side functionality.

#### Archive

`GET /list/archive?date=X&limit=50&order=desc`

RSML uses `mboxrd`

Users can retrieve an `mbox` archive of a set of messages via the `GET /list/archive` endpoint.

The keys accepted are

- `date`: `"today"`, `"all"` or a valid ISO date (default: `"today"`)
- `limit`: an integer of how many emails to show (default: `50`, max: `100`)
- `order`: `desc` or `asc` (default: `desc`)

> The `date` key filters messages by the RSML receipt timestamp, instead of the one specified in the `Date` header

#### Mass Forwarding

The mailing list must forward all the messages posted to all the subscribers.

The server will dynamically add or modify the following headers for mass-forwarded emails:

- `List-ID`: the RFC 2919 identifier for the mailing list, formatted as `display name <list-id>`
- `Precedence`: if enabled, default: `disabled`
- `List-Unsubscribe` and `List-Unsubscribe-Post`: URLs to unsubscribe from the mailing list
- `Date`: will update the header if `fix_date` is enabled

#### Message Ingestion

RSML accepts messages from an external MTA through LMTP.

The LMTP service is responsible only for message ingestion. SMTP, Internet, mail delivery, queuing, and retry handling are responsibilities for the external MTA.

Configuration is expected to be stored in a `TOML`-formatted file. RSML accepts a configuration path as an argument; if no path is provided, it attempts to load `./rsml.toml`; the specified defaults are used.

The following configuration options are available, with the specified values as their defaults.

- `server_secret`: Secret used for generating verification and unsubscription tokens; no default
- `posting_email`: The posting email address (default: `dev@localhost`)
- `display_name`: A display name for the mailing list (default: `rsml list`)
- `list_id`: The List ID (default: `localhost`)
- `archive_limit`, `archive_max`: `limit` in `/list/archive` (default `50`, max `100`)
- `posting`: Whether the `posting` feature is enabled (default `true`)
- `posting_permissions`: Who can post to the mailing list, requires `posting` to be enabled: either `all` or `subscribers` (default: `all`)
- `subscriber_db` and `email_directory`: The path to the Subscriber Database and the Email Directory, as specified below
- `precedence`: The `Precedence` header: can be `list`, or `disabled` (default: `disabled`)
- `fix_date`: Update the `Date` header with the current `UTC` date and time when forwarding or returning messages through the archive endpoint (default: `false`)
- `http_url`: the url to prefix the verify and unsub urls with (default: `http://127.0.0.1:8080`)
- `relay_host` and `relay_port`: hostname and port for the MTA/SMTP server (default: `127.0.0.1` and `25` respectively)
- `http_host` and `http_port`: hostname and port for the HTTP server (default: `127.0.0.1` and `8080` respectively)
- `lmtp_host` and `lmtp_port`: hostname and port for the LMTP server (default: `127.0.0.1` and `8024` respectively)

### Storage

Subscribers list is stored in a `SQLite3` file, by default in `/var/lib/rsml/subscribers.db`

Emails are stored in the `/var/lib/rsml/mail` directory, partitioned by date. Each email is stored as a `YYYY/MM/DD/UID.eml` file, where `YYYY`, `MM`, and `DD` are the RSML receipt year, month, and day, respectively, `UID` is a unique identifier for the email, automatically generated by RSML on receipt. Messages are stored in their original form. Mailing-list headers are added dynamically when messages are forwarded or returned through the archive endpoint.

`UID` is a 16-character lowercase hexadecimal string generated from 8 cryptographically secure random bytes by RSML upon receipt.

> Example email path:
> `/var/lib/rsml/mail/2026/08/22/38da3419974a846f.eml`
